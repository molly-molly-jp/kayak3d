# ゲームデザイン仕様

このドキュメントは `index.html` に実装されているゲーム仕様の記録です。
数値はすべて実測・実コードから抜き出したものです。

---

## 1. 川のモデル

川はすべて 2 次元関数の組み合わせで定義されています。メッシュも物理も同じ関数を参照します。

### 中心線 `cx(z)`

```js
function cx(z) {
  return 38 * Math.sin(z * 0.01180)
       + 10 * Math.sin(z * 0.02500 + 1.3)
       +  2.5 * Math.sin(z * 0.05500 + 0.5);
}
```

波長 532m / 251m / 114m の 3 つの波を重ねることで、大きい蛇行から細かい波まで出ています。
勾配 `cx1(z)` / 曲率 `cx2(z)` も同時に定義してあり、横方向の押し出し計算に使います。

### 川幅 `halfW(z)`

```js
function halfW(z) { return 10.5 + 2.8 * Math.sin(z * 0.0043 + 2.1) + 1.4 * Math.sin(z * 0.0110); }
```

基準半幅 10.5m（= 全幅 21m）。周期の異なる 2 つの波で 8〜15m 幅が変化します。

### 水面高 `riverY(z)`

```js
function riverY(z) {
  const t = clamp((CFG.startZ - z) / (CFG.startZ - CFG.goalZ), 0, 1);
  let y = -t * CFG.totalDrop;              // 全体の緩やかな下り（30m）
  for (const d of DROPS) {
    const u = clamp((d.z - z) / d.w, 0, 1);
    y -= d.h * u * u * (3 - 2 * u);       // 段差（smoothstep で滑らかに落ちる）
    const s = clamp((d.z + d.swellLen - z) / d.swellLen, 0, 1);
    y += d.swell * s * s * (3 - 2 * s);   // 手前のせり上がり
  }
  return y;
}
```

**`riverY()` だけを参照すれば、水面・カメラ・岩・樹木・カヤック・パーティクルが
すべて同じ高さに追従します。**ここを直すと COURSE 全体で高さが変わります。

### 段差（滝）

| z | 落差 `h` | 落ちる距離 `w` | せり上がり `swell` | `swellLen` |
|---:|---:|---:|---:|---:|
| −455 | 2.0m | 5.0m | 0.60m | 9m |
| −1010 | 2.5m | 5.5m | 0.72m | 10m |

**`h / w` の比が「落ちる」かどうかを決めます。**
`w` を小さくすると最大勾配（= 1.5·h/w）が上がり、崖として見えます。

せり上がりは「這い上がって → 踏み抜いて → 落ちる」の 2 拍を作るためのものです。
この実装では最大 -33° まで沈み込み、段差のない区間では -2.7° のままでした。

## 2. コース生成

**固定 seed** を使うため、リトライしてもまったく同じコースになります。

| 対象 | seed | 場所 |
|---|---|---|
| 岩・ゲート | `mulberry32(987654321)` | `buildObstacles()` |
| 樹木 | `mulberry32(424242)` | `buildTrees()` |

### ゲート

- 34 個を川に沿って等間隔に配置
- 旗の横幅は `baseWidth × DIFFS[diff].gateScale`
- 中央を通れば PERFECT（`gateTol` で判定）
- ポールは `FLAG_POLE_H`（2.6m）、旗はその 0.25m 下（2.35m）

**旗の高さは少しずつ上げる。** 遠景（木々や岩）と同じ高さになると
「ゲート」と読み取りにくくなるので 2.6m まで上げた。
上げすぎると川ではなく「門」に見えて現実感が失われ、
先まで見すぎて難易度が下がるので、ここで止める。
値は `index.html` の `FLAG_POLE_H` で調整できます。

### 岩

- `DIFFS[diff].rockPts` を z 方向のコストに加算して、密度を調整
- NORMAL で −120（= 密にする）
- 当たり半径 `rockR`（0.68 / 0.82 / 0.92）

## 3. 操作と物理

### 櫂（ストローク）

| 定数 | 値 | 意味 |
|---|---:|---|
| `strokeRate` | 1.35 | 1 秒あたりの櫂サイクル数（約 0.74s / 櫂） |
| `strokeWin` | 0.34 | 推力のかかるフェーズ幅 |
| `strokeLag` | 0.07 | キー押下から櫂が動くまでの遅れ |
| `strokeLat` | 5.6 | 1 櫂あたりの横推進 |
| `strokeFwd` | 0.85 | 前進漕ぎの加速 |

櫂は 3 フェーズ（**キャッチ → パワー → リカバー**）で回します。
`strokeLat × strokeRate` を一定に保つと、櫂の速さを変えても
**操作の強さは変わらない** ので、難易度調整が安全にできます。

### 抵抗と押し出し

| 定数 | 値 | 意味 |
|---|---:|---|
| `dragLat` | 1.45 | 横方向の水抵抗 |
| `curvK` | 0.42 | カーブで外側へ押される強さ（難易度で上書き） |
| `eddyK` | 0.40 | 乱流（難易度で上書き） |

### 流速

```
targetV = speedBase(11.5) + speedGain(7.5) × progress^0.75 + 前進漕ぎ 2.6 + 落下中の加速
上限 = speedMax (26 m/s)
```

段差の落下中は斜面に従って最大 +4.2 m/s 加速します（重力感）。

## 4. カヤックの動き

### ピッチ（前後傾き）

```js
const slope = (riverY(P.z - 1.7) - riverY(P.z + 1.7)) / 3.4;
kayak.rotation.x = ... + clamp(slope, -0.6, 0.6) * 1.05;
```

±1.7m の**短いサンプル**で局所勾配を取ることで、lip の直前で急激に反応します。

| 場所 | 前後角 |
|---|---:|
| 直線 | −3.4°（わずかに前傾 = 川の下り勾配） |
| せり上がりの頂上 | **+2.3°（起き上がる）** |
| 落下中 | **−33°（最大 1.2m 沈む）** |

> **符号に注意**：この実装では負の z ほど下流です。
> `slope` は下流側で小さくなるため負になり、`+ slope` で機首が下を向きます。
> `- slope` にすると「落ちながら起き上がる」反転になります（実際に踏みました）。

### ロール / 櫂

櫂は 3 フェーズ + バネ減衰の追従で動きます。握り位置は ±0.52m（間隔 1.04m）、
パドル本体は `PADDLE_Z`（艇ローカル z = -0.18m、-Z が船首）に置いています。

**オールは胸の前に置かない。** VRM を 1.3 倍にすると胸が前に出るため、
オールが胸の中に入ってしまい、腕を脱臼したように見えてしまいます。
胸の大きいモデルほど症状が出るので、
`index.html` の `PADDLE_Z` を少し前にずらしています（-0.06m → -0.18m）。
握り点も一緒に前へ動くので、腕はそのまま届きます（IK 誤差 0mm）。

### 船底の見え方

船は水下に 0.39m 沈めてあります。**船底の上端が水面上 0.02m** になる深さなので、
水線には**ごく細い帯だけが覗く**様子になります。

| 部位 | 色 |
|---|---|
| デッキ | 黄色 `0xffd23f` |
| 船底 | デッキより少し濃い黄色 `0xd9a52a` |
| コクピット | 黒 `0x1a1d22` |

**赤にはしません。** 赤にすると水線に出たり消えたりして、
ゲームの内容ではなく「色」に注意が奪われてしまうためです。
目立たせない色なので、視線は水・岩・旗のほうに行きます。

## 5. 視点

| モード | 値 | 描画 | カメラ | 画角 |
|---|:--:|---|---|:--:|
| チェイス | 0 | 全部 | 高さ 1.8m / 後ろ 4.9m + 速度 × 0.105（可変） | 61 + |
| 正面 | 1 | 全部 | 船の前方 2.6m / 水面上 0.34m / 横に 0.40m | 88 + |
| POV | 2 | 既存パドラーの胴・腕を非表示（VRM アバターは後頭部が見える） | 目の位置 (0, VRM.povEyeY, 0.46) | 82 + |

`C` キーは `0 → 2 → 1 → 0` の順に巡回します。

**POV カメラの高さは VRM の頭に合わせて変えます**（`VRM.povEyeY` = 頭骨 + 0.24）。
固定の y=1.30 だと、頭が大きいモデルで頭が視界を塞いでしまうためです。

### 実装上の注意

1. **カメラの高さは「カメラ自身の z の水位」を基準にする。**
   艇の位置の水位で計算すると、段差でカメラ自身が水面下に沈みます
   （実際にそうなりました。水面下に入ると近傍の水面が背面カリングされて平らな帯になります）。
2. **POV のニアクリップは 0.05。**櫂や手首が至近（0.14〜0.30m）にあるため。
3. **POV は完全固定にしない。**厳密に目位置に固定すると、櫂が顔の 0.1m 先になり、
   手の位置（横±0.52m）が画角外へ消えます。わずかな追引が正解です。
4. **正面は追従を固定すること。**船が流れると、追従遅延のためカメラが船に寄ってしまい。
   `camK = 0`（lerp なし）にして、距離を固定する。
   追従延迟を残すと、指定する前方 6.2m から実際には 1.8m になってしまい。
   ゲートが 100% 画面内に収まります。

## 6. サウンド

音声ファイルは 0 個。すべて WebAudio で合成しています。

| 音 | 合成方法 |
|---|---|
| 川音 | ノイズバッファをループ再生 + ローパス（流速でフィルタと音量を変調） |
| 櫂の水音 | ノイズ + 帯域パス、ストローク位相でトリガ |
| 岩の衝突 | 短いノイズバースト + 減衰 |
| 飛沫 | ノイズの短いバースト |

`M` キーでミュート。

## 7. スコアリング

```js
PTS: { gate: 120, perfect: 240, rock: -120 }
```

- 連続ゲートで combo 倍率（最大 ×10）
- 岩に当たると combo リセット + 画面シェイク
- ランク: **S** ≥6000 / **A** ≥4400 / **B** ≥3000 / **C** それ未満
- 全 34 ゲート通過で `PERFECT RUN!`

## 8. 調整のチェックリスト

「ここはもうちょっと直したい」と考えたときは、ここを見る。

| やりたいこと | 触る場所 |
|---|---|
| 滝を大きく／小さく | `DROPS[].h`（落差）と `DROPS[].w`（落ちる距離） |
| 落ちたときの迫力 | `DROPS[].swell` / `swellLen`（せり上がりの高さ・長さ） |
| 落ちるときの最大傾き | `clamp(slope, -0.6, 0.6) * 1.05` の係数 |
| 押し流されやすさ | `DIFFS[].curvK` と `DIFFS[].eddyK` |
| 横幅 | `CFG.halfW` と `halfW(z)` の係数 |
| 旗ゲート的大小 | `DIFFS[].gateScale` |
| 櫂の重さ | `CFG.strokeRate`（`strokeLat` を同時に変えると操作感が保たれる） |
| 得点 | `CFG.PTS` |
| 正面の距離 / 画角 | `updateCamera()` 内の `D = 2.6` / `camMode === 1 ? 88` |
| POV の広さ | `updateCamera()` 内の `camMode === 2 ? 82 : ...` |
